# 固定角色任务交接协议 v3

## 角色

只有四个角色：主控、选题/脚本、制作、独立质检。发布和指标留在主控，不新建第五角色。

## 文件所有权

- 选题/脚本：`research/`、`content/<video_id>/research/`
- 主控：`workflow/`、`brief.md`、`hypothesis_card.md`、`approvals/`、`metrics/`、registry
- 制作：`content/<video_id>/production/`
- 独立质检：`content/<video_id>/qa/`

不得同时编辑同一文件。质检不能修制作文件；制作不能改 brief；执行角色不能批准、改状态、上传或发布。

## 每次任务必须写清

1. `video_id` 和角色；
2. 输入绝对路径与版本/哈希；
3. 本轮唯一假设和保持项；
4. 唯一输出目录；
5. 完成标准与停止条件；
6. 禁止动作；
7. 最多 3 个待决问题。

## 交接文件

使用 `workflow/templates/HANDOFF_TEMPLATE.md`，命名 `handoff_YYYYMMDD_HHMM.md`。必须包含：

- 阶段与结论；
- 完成/未完成；
- 事实、推断、假设分列；
- 输入、输出、证据和哈希；
- BLOCKER/MAJOR/MINOR；
- 回退点和下一负责人；
- 是否有外部动作、付费、上传、下载或非 G 盘写入。

聊天摘要不能替代文件交接。主控读取交接、复核证据并运行 `workflow_control.py audit` 后才能转换状态。

## 会话生命周期

- 默认使用临时子代理，完成交接后结束。
- 只有跨多天、职责稳定、目录独立的角色才建立长期任务；最多 3 个执行任务。
- 一次性安装、单图修复、权限失败和旧版试验不保留长期会话。
- 归档不删除 G 盘产物；先确认 handoff 和证据路径有效。

## 外部动作

- 浏览和只读统计可按任务执行。
- 上传最多做到 `prepare-only`。
- 发布、评论、点赞、关注、私信等动作必须在发生前得到用户确认。
- 不读取或保存密码、Cookie、验证码和令牌。
