# 视频工具与 Skill 引入门

## 目的

GitHub 热度、演示视频和“支持一键生成”都不是采用依据。任何新项目、Skill、Plugin、模型或模板必须先通过本文件，再进入单条视频生产任务。

## 四种结论

1. `ADOPT_SKILL`：结构符合 Codex Skill，来源和许可清楚，安装到 Codex Skill 目录；运行产生的环境、模型和缓存仍放 G 盘。
2. `PIN_REFERENCE`：只把仓库和 commit 固定在 `projects/`，读取实现或复用少量许可清楚的组件，不直接运行完整工作流。
3. `ISOLATED_RUNTIME`：确有不可替代能力，在 `envs/` 建独立环境并在 `models/`、`cache/` 使用专属路径；不能污染主内容环境。
4. `REJECT`：许可、隐私、费用、维护、硬件、存储或内容质量任一项不能接受。

## 必过检查

- 任务价值：明确服务 R1–R7 中哪个角色、替代哪个手工步骤、输入和输出是什么；
- 许可：代码、模型、字体、声音、模板和示例素材分别记录，不把代码开源等同于模型可商用；
- 版本：记录仓库 URL、commit SHA、发布日期/最新提交；不直接跟随浮动 `main`；
- 存储：环境在 `envs/`、模型在 `models/`、缓存和浏览器在 `cache/`、仓库在 `projects/`；无法重定向到 G 盘则拒绝；
- 隐私：默认本地运行；上传音频、视频、文档或提示词必须另行列明服务、保存策略和授权；
- 费用：任何 API、订阅、点数、GPU 云服务或素材购买必须在调用前取得用户批准；
- 硬件：以 RTX 3050 Ti 4GB 和可用 CPU 为现实上限；不得因演示成功就假设大模型可稳定生产；
- 内容质量：必须说明会降低还是增加 PPT 感、AI 味、模板感和叙事同质化；
- 安全：不得获取或保存 Cookie、验证码、浏览器密码或第三方令牌；发布和互动权不因安装工具而下放；
- 回退：必须能删除该项目的独立环境/缓存，而不破坏主工作流。

## 最小验收

### 研究或脚本工具

- 用项目既有的一个公开样本完成导入、去重/结构化和导出；
- 事实、推断、假设字段不能被工具混写；
- 输出可由主控复核，不接受只有聊天结论或不可追溯向量库。

### 视觉或合成工具

- 生成至少一个 1080×1920、30 FPS 的最小竖屏片段；
- 包含真实证据或原创图示，不用未授权素材；
- 记录渲染命令、耗时、文件体积、依赖锁和缓存路径；
- 检查移动端安全区、字幕可读性、透明层/色彩和首尾帧。

### 声音工具

- 使用非敏感中文测试稿，包含数字、英文缩写和技术词；
- 记录模型/音色许可、模型体积、推理硬件、生成耗时和缓存位置；
- 做 ASR 回环、响度、峰值、断句和主观自然度检查；
- 第三方声音克隆直接拒绝，用户本人声音需单独授权。

### 剪辑和 QA 工具

- 在本地完成 ffmpeg/ffprobe 或等价技术检查；
- 能输出 EDL、字幕时间轴、切点/静音/黑帧/响度问题或技术报告；
- QA 工具不得直接修改被检查的成片。

## 接入生产的最后条件

主控把通过结果写入 `workflow/SKILL_INVENTORY.md` 和 `workflow/AGENT_SKILL_ASSIGNMENTS.md`，并在单条视频的 production manifest 中记录实际版本、路径、输入、输出和哈希。工具链最小测试通过不等于 brief、预算、声音授权或发布已批准。
