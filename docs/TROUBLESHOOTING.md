# 常见问题

## 工作台打不开

在项目目录执行 `python manage.py doctor`，再运行 `python manage.py serve`，保留终端查看错误。若端口冲突，改为 `python manage.py serve --port 8877`。健康检查地址为 `/api/health`，返回的 root 应与当前副本一致。

Windows 双击入口默认选择 `.venv`、旧 `envs/content` 或 PATH 中 Python；找不到 Python 时先完成 Python 安装。前台命令能运行而双击不能运行时，检查 Windows 的 Python 应用执行别名、PowerShell 错误和 `workspace/workbench/runtime/` 日志。

## 草稿或项目怎么没有了

先核对启动的是不是同一个项目副本、同一个账号档案。草稿按账号、项目、动作隔离；它不在浏览器 localStorage 作为唯一来源。更新源码不应覆盖本地 `data/`。`manage.py init` 不覆盖已存在文件。

## 保存要求后没有自动出图

查看 Skill 计划和图片队列。缺少 Skill 时先补齐；READY 需要 Codex 执行方领取，网页本身不加载生图模型。计划、卡片和真实产物有不同状态。没有生成工具时记录阻塞，不能把任务卡当成成品。

## Flova 没有安装、没有权限或积分不足

先检查 `DOUYIN_FLOVA_CLI` 和 PATH，再设置自己的 `DOUYIN_FLOVA_SKILL_ID`，重新启动工作台与编译任务卡。缺少私人 Skill ID 会在执行前提示配置。登录、订阅与积分由自己的平台账号提供，公开仓库不附带。

等待用户选择时检查原始选项；已提交过的任务使用恢复操作，保留项目、运行和导出 ID。不要为了消除错误重复提交同一镜头。

## 为什么 audit 是 BLOCKED

`audit` 是生产研究与内容证据审计，不是安装检查。空白仓库没有真实研究样本、评论需求、brief 批准与 QA，因而可能阻断。网页仍可使用。按工作流补齐真实资料，不要复制维护者运营记录或伪造通过。

## 为什么测试跳过

真实媒体集成测试要求 FFmpeg 与 ffprobe；Windows 启动器测试要求 Windows PowerShell。没有这些环境时会说明跳过原因。测试计数应同时报告通过与跳过，跳过不算相关能力已经验证。

## 图片导出很大但上传后模糊

区分原生细节、导出尺寸和平台压缩。普通放大不会增加真实细节。保存原图、发布图和手机预览，避免多次 JPEG 重压缩；最终需看平台草稿/发布页的实际效果。本仓库没有默认保证有效的超分模型。

## 项目从一台电脑迁移到另一台

复制源码与本地数据后重建环境；检查 manifest 中旧的绝对素材路径。缓存和虚拟环境可重建，账号会话重新登录。现阶段已有作品记录不是完全无感搬迁；详见安装指南的迁移说明。

## 是否已经全自动发布或监控热点

当前网页的发布适配输出 prepare-only 计划和命令预览，实际浏览器操作需交接。没有默认启用的热点监控或定时运营 worker。项目中可见流程和按钮不等于外部账号已配置、授权或执行。

## 如何反馈问题

附上 Python/操作系统版本、`doctor` 结果、复现步骤、预期与实际行为，以及脱敏后的错误。不要上传 Cookie、验证码、API Key、CLI 凭证或私人素材。公开仓库只适合源码与可公开示例，运营目录已被 Git 排除。
